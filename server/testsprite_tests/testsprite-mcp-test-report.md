## 4️⃣ Key Gaps / Risks

> 1 / 1 generated test passed, but the generated suite is **happy-path only**.

- **No validation-failure coverage.** The AI plan generated zero `400` cases, so
  `validatePostData` is completely unverified by TestSprite. Every rule in it
  (missing field, empty string, whitespace-only title, wrong type for
  `category_id` / `status_id`, `status_id` out of {1,2}, image not a URL, length
  caps) is a gap. These are covered instead by the hand-written
  `server/tests/postValidation.test.mjs` (unit) and
  `server/tests/posts.create.integration.test.mjs` (supertest).
- **`PUT /posts/:postId` has no `validatePostData`.** Update accepts invalid /
  missing fields straight into the `UPDATE` query — not surfaced by the AI test.
- **Auth is not negatively tested.** The generated test logs in through the mock
  Supabase (which ignores the password), so `401` / `403` paths on protected
  routes are never checked.
- **Mock persistence only.** `utils/db.mjs` is an in-memory `MockPool`; the test
  confirms routing + response contract + in-memory round trip, not real SQL,
  constraints, or Supabase storage.
- **Guessed credentials.** `TC001` hard-codes `admin@example.com` /
  `AdminPass123!`; it passes only because the mock auth accepts any password for a
  pre-registered email. Against a real auth layer this test would fail at login.
